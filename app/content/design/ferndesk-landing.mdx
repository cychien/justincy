[Ferdesk](https://ferndesk.com/) 是一款 Help Center SaaS，我覺得它 landing page 的資訊架構編排與 UI 元素運用給我很多啟發，底下分享那些我學到的事。

## 資訊架構 & 介面設計

<ImageAnnotations mode="fullscreen">
  <Annotation y={0} to={756} title="Hero">
    1. 大標題寫核心價值、能為 users 解決什麼問題，賣的不是 SaaS 本身，**而是幫 user 解決什麼事**。
    2. 標題下的 description 敘述 Ferndesk 是一款什麼樣的產品，並簡單描述它是如何做的，如何幫你有效解決問題。**description 的重點在告訴 visitors 你的實際 (創新) 解法，讓他們知道你不是唬爛，有興趣繼續看下去**。
    3. description 下緊接著 CTA，有些 visitors 感興趣就會直接點擊了。
    4. CTA 下的小字敘述一些附加誘因，讓整個 offer 更吸引人。
    5. 右側圖片放實際產品圖或 demo, 增加可信度以及更多購買推力。
  </Annotation>

  <Annotation y={756} to={1105} title="Testimonial">

  <Annotation y={1105} to={1817} title="痛點">
    敘述你的目標客群常會遇到的、很痛的問題，**這裡的目標是要讓他們回憶這些痛苦，並相信這些點真的麻煩，真的值得並有可能被優化**。
  </Annotation>

  <Annotation y={1817} to={2735} title="解法 + 簡易運作流程">
    正式提出解法。

    **人們想要知道解法，但又不希望認知負擔過大**，看不懂他們也會走。所以這一步就是盡可能簡單的**告訴 visitors，我們是真的有實際並可行的 solution 能解決，並且很簡單**。

    隨後再慢慢深入解釋解法。
  </Annotation>

  <Annotation y={2735} to={3820} title="更實際的解法">
    這一步開始更深入解釋解法，可以搭配圖來說明。
  </Annotation>

  <Annotation y={3820} to={4665} title="豐富的功能">
    主要問題解法說完，為了使 offer 更誘人，可以列出更多產品擁有的功能。這一個 section 就是**要讓 visitors 覺得還有這麼多功能，真好！**
  </Annotation>

  <Annotation y={4665} to={6403} title="Testimonial">

  <Annotation y={6403} to={6901} title="阻礙破解：Easy Migration">
    你要回答自己：**visitors 看到這裡，為什麼還沒購買或註冊？**

    有極大概率是，**他們有其他的 concerns**，因此可以花一些篇幅來消除他們的 concerns。

    解法後的這些 section 就是要**猜他們為什麼還沒買，我能如何破解阻礙**。
  </Annotation>

  <Annotation y={6901} to={7844} title="Pricing">
    其中一個阻礙就是 Pricing, Pricing 務必說得清楚。

    這一塊的 Pricing 資訊架構可以學習：

    1. Plan 名稱
    2. 金額
    3. 適合誰
    4. 有什麼內容
    5. 最多人買什麼
  </Annotation>
